## 2024-10-29 - OpenPyXL Styling and Pandas iterrows Botteneck
**Learning:** Python reporting scripts combining pandas and openpyxl are suffering from two distinct O(n) bottlenecks: 1) Pandas `iterrows()` is incredibly slow for writing Excel data and yields row data as series (forcing `.tolist()` conversions), and 2) Instantiating new `PatternFill` style objects inside nested row/cell formatting loops wastes massive memory and CPU since OpenPyXL allows style objects to be safely shared. Furthermore, some scripts contain a dangerous anti-pattern: `ws.delete_rows(1)`. This was likely added by a developer who incorrectly assumed `iterrows()` returned the dataframe header as the first row. Removing the header via `delete_rows(1)` when not necessary actually corrupts the dataset by removing legitimate data.
**Action:** Always replace `iterrows()` with `openpyxl.utils.dataframe.dataframe_to_rows(df, index=False, header=False)` for a ~4-5x speedup. Always declare formatting objects (`PatternFill`, `Font`, etc.) once outside of the iteration loop and apply those cached references inside the loop. Lastly, when replacing `iterrows()` with `dataframe_to_rows(header=False)`, always verify and remove any subsequent `ws.delete_rows(1)` commands to prevent data loss.
